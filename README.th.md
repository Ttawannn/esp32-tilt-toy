# esp32-tilt-toy

[English](README.md) · **ภาษาไทย**

พวงกุญแจ **ESP32 30-pin / ESP32-C3 SuperMini / ESP32-C6 SuperMini + BMI160 / MPU6050** ที่เล่นด้วยการเอียงและเขย่า มีเว็บเลือกบอร์ด จอ และโมดูลเซนเซอร์ ทดลองเล่น และแฟลชผ่าน USB พร้อมหน้าตั้งค่าบนตัวเครื่องที่เปิดจากมือถือ

**เว็บ installer + preview:** https://ttawannn.github.io/esp32-tilt-toy/

## ภาษา

หน้าเว็บ installer และ preview ใช้ **ภาษาอังกฤษเป็นค่าเริ่มต้น** กดปุ่ม **ภาษาไทย** ด้านบนเพื่อเปลี่ยนภาษา หรือกด **English** เพื่อกลับเป็นภาษาอังกฤษ เบราว์เซอร์จำภาษาที่เลือกไว้ การสลับภาษาเปลี่ยนปุ่ม คำอธิบายโหมด ผังสาย คู่ขา และสถานะเฟิร์มแวร์ทันที โดยคงบอร์ด จอ โหมด และความคืบหน้าการฝึกต่อสายไว้ หน้าตั้งค่าบนตัวเครื่องด้านล่างเป็นหน้าแยกที่ให้บริการจากเฟิร์มแวร์

## เปลี่ยนหลัง v0.1.4

- **5 โหมด**: น้ำปกติ, น้ำกระฉอก, น้ำพิกเซล, ตาการ์ตูน และตาหุ่นยนต์ ลบน้ำมีแรงเฉื่อย, น้ำวน, น้ำสมจริง, เขาวงกต, ลูกแก้วหิมะ, Pong และลูกเต๋าออก เครื่องที่บันทึกไว้ในโหมดที่ถูกลบจะเริ่มที่น้ำปกติ
- **ตาหุ่นยนต์** 8 อารมณ์ เลือกบนมือถือ หรือเลือก *เล่นวนทุกอารมณ์*
- **ตั้งแกนเซนเซอร์บนเครื่อง**: กด BOOT ค้าง 5 วินาที (หรือกดปุ่ม *ตั้งแกนอัตโนมัติ* ในหน้ามือถือ) วางเครื่องราบหน้าจอขึ้นจนแถบเต็ม แล้วตั้งเครื่องให้ขอบล่างลง เครื่องจะคำนวณว่าแกนไหนของเซนเซอร์ชี้ไปทางไหนแล้วบันทึกให้ จึงติดโมดูลหันทางไหนก็ได้ (ขอให้ขนานกับขอบจอ)
- **แก้ทิศของ accelerometer**: เซนเซอร์อ่านค่า +1 g ชี้ขึ้นตอนนิ่ง motion filter จึงใช้ทิศตรงข้ามเป็นแรงโน้มถ่วง แกนจอในหน้ามือถือ (X ขวา, Y ลง, Z เข้าจอ) ตรงกับทิศจริงแล้ว preview บนเว็บก็จำลองแบบเดียวกัน
- **ไฟล์สำหรับ Arduino IDE**: ใต้ปุ่มแฟลชมีส่วน *แก้โค้ดเองใน Arduino IDE* ให้ดาวน์โหลด คัดลอก หรือดูไฟล์ `.ino` ของบอร์ดและจอที่เลือก พร้อมตารางตั้งค่าเมนู Tools และความหมายของแต่ละค่า และรายชื่อไลบรารี `npm run build` สร้างไฟล์ครบ 18 ชุดไว้ใน `dist/arduino/` จาก `firmware/tilt_toy` ด้วย `scripts/arduino-sketch.mjs` โดยรวม header ทุกไฟล์ไว้ในไฟล์เดียว ล็อกบอร์ดและจอด้วย `#define` และ include เฉพาะไลบรารีของจอนั้น
- **Serial Monitor (115200)**: บอกสาเหตุการรีเซ็ตตอนบูต เหตุการณ์ปุ่ม BOOT และ Wi-Fi และพิมพ์ FPS / เวลา solver ทุก 1 วินาที
- **น้ำกระฉอก**: น้ำปกติที่รับแรงขยับและการหมุนของเครื่องจริง ขยับหรือโยกแล้วน้ำค้างอยู่ก่อนแล้วกระฉอกกลับ และน้ำพิกเซลใช้ตารางขนาดเดียวกับน้ำปกติทุกจอ
- **น้ำแบบจำนวนเต็ม**: solver FLIP คำนวณแบบ fixed-point Q16 ทั้งหมด เพราะ C3/C6 ไม่มี FPU ดูหัวข้อ [โหมดน้ำ (FLIP/PIC)](#โหมดน้ำ-flippic)

## เพิ่มใน v0.1.4

- **น้ำพิกเซล (pixel-flow)**: น้ำ 1 เม็ดเท่ากับ 1 ช่องบนจอ วาดเป็นตารางจุดแบบจอ LED ผิวน้ำสว่างกว่า หยดเดี่ยวกระเซ็นได้ เอียงแล้วผิวน้ำเอียงตามมุมจริง คำนวณด้วยเลขจำนวนเต็ม จอ TFT ส่งเฉพาะเม็ดที่เปลี่ยนที่ 30 Hz
- **น้ำสมจริง (water-full)**: ใช้ FLIP เดิม รวมแรงเอียง แรงกระตุก และแรงหมุนรอบจอในโหมดเดียว สีและ blend เฉพาะโหมด preview หมุนได้ ±180° ต่อเนื่อง มีปุ่มหมุนเครื่องตัวอย่าง

รวมเป็น 10 โหมด ID เดิม 0–7 ใน NVS ไม่เปลี่ยน

## เพิ่มใน v0.1.3

- อ่าน BMI160 / MPU6050 จาก FIFO ที่ 100 Hz และขยาย gyro เป็น ±2000°/s เพื่อเก็บการหมุนระหว่างส่งภาพจอ
- รวม accelerometer กับ gyro เป็น quaternion และแยกแรงขยับออกจากแรงโน้มถ่วง แยกเป็นน้ำปกติ, น้ำมีแรงเฉื่อย (ซัดสวนการกระตุก) และน้ำวน (แรง Euler / Coriolis / centrifugal เมื่อหมุนรอบจอ)
- ตั้งทิศแกน X/Y/Z และกลับเครื่องหมายจากมือถือได้ เก็บใน NVS และใช้กับทั้ง accelerometer และ gyro ทุกการหมุนภาพ
- หน้ามือถือแสดง gravity, ความเร็วหมุน และแรงขยับของแต่ละแกน ส่วน preview มีวางราบ หมุน หยุดหมุน และกระตุกสี่ทิศ

นี่เป็นฐาน motion และโหมดน้ำของแผน 6DOF

## โหมดในเครื่อง

ทุก firmware มี 5 โหมด กดปุ่ม **BOOT บนบอร์ด** สั้น ๆ เพื่อสลับ หน้าจอใช้เป็นพื้นที่เล่นทั้งหมด ไม่มีชื่อโหมด ตัวเลข หรือกรอบ ค่าต่าง ๆ ไปแสดงบนหน้าเว็บในมือถือแทน ข้อความบนจอมีแค่ 2 กรณี คือชื่อ Wi-Fi กับ IP ขณะเปิดโหมดตั้งค่า และ `IMU NOT FOUND` เมื่อไม่พบเซนเซอร์

| โหมด | เล่นอย่างไร |
| --- | --- |
| **น้ำปกติ (water)** | น้ำไหลตามการเอียง เขย่าให้เกิดคลื่น พิกเซลสี่เหลี่ยมและผิวน้ำสีจาง |
| **น้ำกระฉอก (water-slosh)** | หน้าตาเหมือนน้ำปกติ แต่กระฉอกไปมาเหมือนน้ำจริงเมื่อขยับหรือโยกเครื่องซ้ายขวา ใช้แรงขยับและการหมุนที่วัดได้ ไม่มีแรงลากที่ผนัง เขย่าแล้วยังเกิดคลื่นได้ |
| **น้ำพิกเซล (pixel-flow)** | น้ำเม็ดละเอียดแบบจอ LED เอียงให้ไหล กระตุกให้ซัด เขย่าให้กระเซ็น |
| **ตาการ์ตูน (pet)** | ตาการ์ตูนมองตามทิศที่เอียง |
| **ตาหุ่นยนต์ (robot)** | ตาหุ่นยนต์กะพริบ กลอกตา และมองตามการเอียง เลือกอารมณ์บนมือถือได้ 8 แบบ (ปกติ ดีใจ โกรธ เศร้า ง่วง ตกใจ สงสัย หลงรัก) หรือ *เล่นวนทุกอารมณ์* (`auto`) แสดงทีละอารมณ์ 3.5 วินาที เขย่าแล้วตกใจครู่หนึ่ง |

### โหมดน้ำ (FLIP/PIC)

โหมดน้ำจำลองของไหลแบบ FLIP/PIC บนกริด MAC ดัดแปลงจาก [Ten Minute Physics #18](https://matthias-research.github.io/pages/tenMinutePhysics/18-flip.html) ของ Matthias Müller (MIT license) ESP32-C3 และ C6 ไม่มี FPU จึงคำนวณแบบ fixed-point Q16 ทุกขั้นตอนต่ออนุภาคและต่อช่องเป็นจำนวนเต็ม เหลือ float แค่ตอนเตรียมค่าต่อเฟรม มีโค้ดสองชุดที่ได้ผลตรงกันทุกบิต (test รัน 300 step แล้วเทียบทุกค่า)

- `firmware/tilt_toy/flip_fluid.h`: C++ จองหน่วยความจำคงที่ไว้สูงสุด 400 cells / 900 particles (~32 KB รวมกริดพิกเซล) ไม่ allocate ระหว่างรัน
- `web/fluid.js`: JavaScript สำหรับ preview บนเว็บ

น้ำปกติ น้ำกระฉอก และน้ำพิกเซลปรับระดับน้ำได้ 10–90% ลำดับปุ่ม BOOT คือ น้ำปกติ → น้ำกระฉอก → น้ำพิกเซล → ตาการ์ตูน → ตาหุ่นยนต์ NVS key `toyMode` เก็บ 0 น้ำปกติ, 1 น้ำพิกเซล, 2 ตาการ์ตูน, 3 ตาหุ่นยนต์, 4 น้ำกระฉอก และ `robotMood` เก็บอารมณ์ที่เลือก firmware ก่อนหน้าเก็บเลขโหมดแบบ 10 โหมดไว้ใน `mode` เปิดเครื่องครั้งแรกหลังอัปเดตจะแปลงให้ น้ำพิกเซลกับตาการ์ตูนคงเดิม โหมดที่ถูกลบเริ่มที่น้ำปกติ

ทั้งสองชุดใช้ fixed step 25 ms (ไม่เกิน 2 step ต่อเฟรม เฟรมที่ช้าจึงไม่ลากเฟรมถัดไป) มีภาชนะทรงกลมสำหรับจอ GC9A01 หาเพื่อนบ้านด้วย linked-cell และแรงโน้มถ่วงมาจาก motion filter ของเซนเซอร์ที่ตรวจพบ น้ำปกติใช้แรงเอียงอย่างเดียว น้ำกระฉอกเพิ่มแรงขยับและแรง Euler, Coriolis, centrifugal จากการหมุนรอบแกนจอ ขนาดกริดปรับตามจอ ส่วนจอกลมใช้ 20×20

ต้องวัดเวลา solver บนบอร์ดแต่ละรุ่นจริง ดูได้จากช่อง Solver ในหน้าตั้งค่าบนมือถือ (หรือ `simMs` ใน `/api/status`) ถ้าเกินราว 25 ms ภาพจะกระตุก ให้ลดขนาดกริดหรือระดับน้ำ ข้อความ license อยู่ที่ [web/licenses/ten-minute-physics.txt](web/licenses/ten-minute-physics.txt) และที่ `/license` บนตัวเครื่อง

### โหมดน้ำพิกเซล (Pixel Flow)

ไม่ใช้ FLIP แต่ละเม็ดน้ำอยู่ในช่องของตารางจอและมีความเร็วของตัวเอง (fixed-point Q8) ทุก step ที่ 30 Hz เม็ดที่ลึกที่สุดตามแรงโน้มถ่วงขยับก่อน ชนแล้วเบี่ยง 45° ไปทางลาดลง เม็ดที่วางอยู่ไหลออกข้างเพื่อให้ผิวราบ และย้ายเม็ดจากจุดสูงสุดของผิวไปจุดต่ำสุดทีละไม่เกิน 3 เม็ด เพื่อให้ผิวเอียงตามมุมจริงแทนที่จะติดอยู่แค่ 8 ทิศของตาราง แรงที่ใช้คือแรงโน้มถ่วง + แรงกระตุก (แรงขยับที่เกิน 0.4 m/s²) ไม่ใช้แรงหมุน

- `firmware/tilt_toy/pixel_flow.h` (class `PixelDrops`) และ `web/pixel-flow.js` เป็นเลขจำนวนเต็มทั้งหมด จึงให้ผลตรงกันทุกบิต (มี test เทียบ C++/JS) จองหน่วยความจำคงที่ สูงสุด 2,048 ช่อง / 1,900 เม็ด ราว 31 KB (บวกอีก 2 KB ใน sketch สำหรับภาพที่ส่งไปแล้ว)
- ตาราง: ขนาดช่องเท่ากับพิกเซลของน้ำปกติทุกจอ จอ 240×240 ระยะ 7 px (เม็ด 6 px + ร่อง 1 px) 33×33 ช่อง, Mini TFT 3 px 25×52 / 52×25, OLED 3 px 41×20 ภาชนะมุมโค้งบนจอเหลี่ยม วงกลมบน GC9A01 และสี่เหลี่ยมบน OLED
- สี: ผิวน้ำ, ละอองที่เคลื่อนเร็ว และเนื้อน้ำ 4 เฉดตามความลึก มีประกายเปลี่ยนช้า ๆ ช่องว่างเล็ก ๆ กลางก้อนน้ำวาดเป็นน้ำ
- จอ TFT ไม่ผ่าน framebuffer: เทียบกับภาพเดิมแล้วเขียนเฉพาะเม็ดที่เปลี่ยน OLED, หน้าจอ Wi-Fi และ `IMU NOT FOUND` ยังใช้ทางเดิม OLED คงเฟรม 50 ms เพราะใช้ I²C ร่วมกับเซนเซอร์
- `simMs` และ `particles` ใน `/api/status` เป็นของโหมดนี้เมื่อเปิดอยู่

## บอร์ดที่รองรับ

| ตัวเลือกในเว็บ | ชิป / โมดูล | USB สำหรับแฟลช | Flash |
| --- | --- | --- | --- |
| ESP32 30-pin | ESP32, ESP-WROOM-32 / DevKit V1 รุ่น 30 ขา | USB-to-Serial บนบอร์ด | 4 MB |
| ESP32-C3 SuperMini | ESP32-C3 | USB Serial/JTAG | 4 MB |
| ESP32-C6 SuperMini | ESP32-C6 | USB Serial/JTAG | 4 MB |

เลือก **รุ่นบอร์ด** ก่อนเลือกจอ เว็บเปลี่ยนผัง GPIO และไฟล์เฟิร์มแวร์ตามบอร์ด และจำตัวเลือกหลัง reload บอร์ดเดิมที่ยังไม่ได้เลือกจะเริ่มที่ C6 รุ่น ESP32 30-pin ใช้กับ ESP-WROOM-32 / DevKit V1 ตามตาราง; ให้เทียบชื่อ GPIO ที่พิมพ์บนบอร์ดจริง

## จอที่รองรับ

| จอ | Controller | โปรไฟล์ |
| --- | --- | --- |
| TFT 80×160 แนวตั้ง | ST7735S Mini 160×80, rotation 0 | `tft-80x160` |
| TFT 160×80 แนวนอน | จอเดียวกัน, rotation 1 | `tft-80x160-landscape` |
| GMT130 240×240 | ST7789, 7 ขา ไม่มี CS | `gmt130-240x240` |
| TFT กลม 240×240 | GC9A01 | `tft-240x240-gc9a01` |
| OLED 128×64 | SSD1306, I²C 0x3C/0x3D | `oled-128x64` |

เลือก **TFT 80×160 → แนวของจอ → แนวตั้ง / แนวนอน** ในเว็บ installer ภาพ preview และไฟล์แฟลชเปลี่ยนตามแนวที่เลือก เว็บจำตัวเลือกหลัง reload เมื่อติดตั้งโปรไฟล์ Mini TFT คนละแนว firmware จะใช้ rotation ของโปรไฟล์ใหม่นั้น แม้มีค่าเดิมใน NVS เมื่อบูตครั้งต่อไปยังคงค่าที่เปลี่ยนจากมือถือได้ โดยเลือก **แนวจอ / หมุนภาพ** แล้วกดบันทึก

แต่ละคู่บอร์ดและโปรไฟล์จอมี merged binary แยกกัน รวม **15 ชุด / Flash 4MB** เว็บตรวจรุ่นชิป บอร์ด จอ และ checksum ก่อนเปิดปุ่มแฟลช ทุก manifest ระบุ `hardwareTested: false` เพราะยังไม่ได้ทดลองกับบอร์ดและจอจริง และยังไม่มีผลวัด FPS กระแสไฟ หรืออายุแบตเตอรี่ ส่วนจอ SH1106 และ ST7735 ที่ใช้ offsets ต่างจาก Mini160×80 ต้องเพิ่มโปรไฟล์ใหม่

| CS / DC / RST | 27 / 26 / 25 | 10 / 3 / 1 | 18 / 19 / 20 |
| ปุ่ม BOOT บนบอร์ด (ไม่ต้องต่อเพิ่ม) | 0 | 9 | 9 |

ใช้ BOOT หลังเครื่องเริ่มทำงาน: กดสั้นเปลี่ยนโหมด กดค้างแล้วปล่อยหลัง 2 วินาทีเปิด/ปิด Wi-Fi หรือหลัง 5 วินาทีเข้าโหมดตั้งแกน ระหว่างกดค้าง จอจะบอกว่าปล่อยตอนนี้จะได้อะไร ส่วนปุ่ม RST ใช้รีสตาร์ตเครื่อง ให้ปล่อย BOOT ขณะเปิดเครื่องหรือกด RST เพื่อบูตเล่นตามปกติ; กด BOOT ค้างช่วงนั้นจะเข้าโหมดแฟลช [การเลือก boot mode ของ ESP32-C6](https://docs.espressif.com/projects/esptool/en/latest/esp32c6/advanced-topics/boot-mode-selection.html)

ผังเต็ม ข้อควรระวังเรื่องไฟ backlight และ checklist ทดสอบอยู่ใน [docs/HARDWARE.md](docs/HARDWARE.md)

### โมดูลเซนเซอร์

เฟิร์มแวร์ทุกโปรไฟล์จอตรวจชนิดเซนเซอร์อัตโนมัติจาก Chip ID เมื่อเปิดเครื่อง ไม่ต้อง build แยกตามเซนเซอร์ เลือก **โมดูลเซนเซอร์** ในเว็บเพื่อดูผังสายให้ตรงกับโมดูลที่ใช้ ต่อเซนเซอร์หนึ่งตัวต่อเครื่อง โดยให้แกน X/Y สัมพันธ์กับจอ

| เซนเซอร์ | I²C address ที่ตรวจ | การตั้งขาเลือก I²C / address | การเคลื่อนไหว |
| --- | --- | --- | --- |
| BMI160 | `0x68` / `0x69` | CS/CSB → 3V3, SDO/SA0 → GND สำหรับ `0x68` หรือ 3V3 สำหรับ `0x69` | แรงเร่ง + gyro |
| MPU6050 / GY-521 | `0x68` / `0x69` | AD0 → GND สำหรับ `0x68` หรือ 3V3 สำหรับ `0x69` | แรงเร่ง + gyro |

ทั้งสองรุ่นเป็น IMU 6 แกน (แรงเร่ง + gyro) ตั้งค่าอ่านประมาณ 100 Hz, ช่วงแรงเร่ง ±8 g และ gyro ±2000°/s อ่าน FIFO เป็นชุดและป้อน sensor fusion ทีละ sample ที่ 10 ms ค่า roll/pitch มาจาก gravity ที่กรองแล้ว ส่วน yaw เป็นมุมสัมพัทธ์ที่อาจลอย ไม่มีเข็มทิศ หากอ่าน I²C ล้มเหลวติดกัน 5 ครั้งจะแสดงว่าไม่พบเซนเซอร์ ให้ตรวจสายแล้วเปิดเครื่องใหม่

หน้าเว็บมีกราฟรูปอุปกรณ์และเส้นต่อสายตามบอร์ด จอ และเซนเซอร์ที่เลือก พร้อมรายการว่า pin ไหนต่อ pin ไหน กดสายเพื่อไฮไลต์คู่ขา หรือเลือก “ลองลากต่อสาย” เพื่อฝึกต่อได้ทั้งลากสาย แตะทีละขา และใช้คีย์บอร์ด ระบบตรวจคู่ขาและนับสายที่ต่อแล้ว โดยใช้ GPIO ตามเฟิร์มแวร์ของบอร์ดนั้น

## แฟลชผ่านเว็บ

1. เปิดเว็บ installer ด้วย **Chrome / Edge บนคอมพิวเตอร์** (ต้องเป็น HTTPS หรือ localhost)
2. เลือกบอร์ดและจอให้ตรงกับรุ่นที่ใช้ เว็บจะตรวจรุ่นชิป ขนาดไฟล์ และ SHA-256 ก่อนเปิดปุ่มแฟลช
3. ต่อสาย USB ที่รับส่งข้อมูลได้ แล้วกด **เชื่อมต่อและแฟลช** ถ้าเป็นการติดตั้งครั้งแรก ให้เลือก erase เพื่อเริ่มจากค่าเริ่มต้นของโปรไฟล์ (การ erase จะลบค่าที่บันทึกไว้)

ถ้าไม่เจอพอร์ต ให้ปิด Serial Monitor แล้วกด BOOT ค้างไว้ขณะเสียบสาย USB ปล่อย BOOT แล้วลองใหม่

หน้าต่างแฟลชแสดงขั้นตอนปัจจุบัน เวลาที่ผ่านไป เปอร์เซ็นต์ดาวน์โหลด และเปอร์เซ็นต์เขียนข้อมูลตั้งแต่ 0% กด **ดู log การแฟลช** เพื่อดูข้อความจากตัวแฟลช ถ้ารอ bootloader โดยไม่มีข้อมูลใหม่เกิน 30 วินาที จะแสดงวิธีกด BOOT/RST ถ้าดาวน์โหลดไม่มีข้อมูลใหม่ 30 วินาที จะแจ้งข้อผิดพลาดให้ลองใหม่ ส่วนการสื่อสารกับบอร์ดใช้ timeout ของ esptool

ใช้ preview บนเว็บทดลองเล่นได้โดยไม่ต้องต่อบอร์ด มีแถบเลื่อนจำลองการเอียงและก้ม/เงย กับปุ่มเขย่า ในโหมดน้ำปรับระดับน้ำได้ เปิดแสดงกริดได้ และลากบนจอเพื่อกวนน้ำได้ น้ำกระฉอกและน้ำพิกเซลมีปุ่มกระตุกสี่ทิศ น้ำกระฉอกหมุนภาชนะด้วยความเร็วเหมือนมือคนเมื่อเลื่อนแถบเอียง และน้ำพิกเซลลากบนจอเพื่อผลักน้ำได้ ตัวควบคุมแสดงตามโหมดที่เลือก

## ตั้งค่าจากมือถือ

1. เมื่อเครื่องเริ่มทำงานแล้ว กดปุ่ม BOOT บนบอร์ดค้าง 2 วินาที แล้วปล่อย เพื่อเปิด Wi-Fi
2. เชื่อมต่อ `TiltToy-xxxx` รหัส `tilttoy32` แล้วเปิด `http://192.168.4.1`
3. ด้านบนของหน้าแสดงค่าสดที่อัปเดตทุก 1 วินาที ได้แก่ โหมด, roll/pitch, FPS, เวลา solver และจำนวนอนุภาค (โหมดน้ำ) และ heap ว่าง
4. ตั้งโหมด ระดับน้ำ ความไว และการหมุนภาพ แล้วกดบันทึก สำหรับจอ TFT ตั้ง inversion ได้ และสำหรับ ST7789 ตั้ง SPI mode ได้ ค่าทั้งหมดเก็บใน NVS
5. กดปิด Wi-Fi แล้วเล่นต่อ หรือรอให้ปิดเองหลัง 3 นาที

หน้าเครื่องแสดงชื่อบอร์ด พร้อมชื่อและ I²C address ของเซนเซอร์ที่ตรวจพบ ให้วางเครื่องนิ่งตอนเปิดเครื่องหรือตอนกดคาลิเบรต gyro ของ BMI160 / MPU6050 และตรวจแผงทดสอบแกนแล้วตั้ง X/Y/Z ให้ตรงกับจอ: X ไปขวา, Y ลงล่าง, Z เข้าไปในจอ เลือกแกนไม่ซ้ำและใช้การหมุนที่รักษาระบบแกนขวา หากกลับเครื่องหมายให้กลับสองแกนพร้อมกัน คาลิเบรตขณะเคลื่อนไหวจะถูกปฏิเสธ

| Endpoint | หน้าที่ |
| --- | --- |
| `GET /api/status` | version, `board`, `boardName`, `chipFamily`, profile, โหมด, `mood`, `waterColor`, ค่าตั้ง, `imu`, `sensor`, `sensorAddress` (เลขฐานสิบ), `gyro`, roll/pitch, `fps`, `simMs`, `particles`, `freeHeap`, `axisX/Y/Z`, `gravity`, `omega`, `linear` (array X/Y/Z), `yaw`, `stillMs`, `fifoResets` |
| `POST /api/config` | `mode`, `fill`, `sensitivity`, `rotation`, `invert`, `spiMode`, `axisX`, `axisY`, `axisZ` (±1=X, ±2=Y, ±3=Z) |
| `POST /api/shake` · `/api/calibrate` · `/api/close` | เขย่า, คาลิเบรต gyro, ปิด Wi-Fi |
| `GET /license` | ข้อความ MIT license ของ FLIP solver |

`mode` รับ `water`, `water-slosh`, `pixel-flow`, `pet`, `robot` และ `mood` รับ `auto`, `normal`, `happy`, `angry`, `sad`, `tired`, `surprised`, `suspicious`, `love` และ `waterColor` รับ `classic` (สองสีแบบเดิม) หรือ `gradient` (น้ำปกติและน้ำกระฉอกไล่เฉดตามความลึกด้วยชุดสีของน้ำพิกเซล ไม่มีการกระพริบ เม็ดน้ำจะเปลี่ยนเฉดเมื่อความลึกเลยช่วงของเฉดนั้นเกินหนึ่งเม็ด ผิวน้ำกระเพื่อมจึงไม่ทำให้น้ำด้านล่างกระพริบ เก็บใน NVS key `waterGradient`)

## พัฒนาบนเครื่อง

ใช้ Node.js 22 ขึ้นไป มี binary ที่ build แล้วอยู่ใน `web/firmware/` จึงเปิดเว็บได้โดยไม่ต้องติดตั้ง Arduino toolchain

```sh
npm ci
npm test
npm run build
npm run dev
```

จากนั้นเปิด `http://localhost:4173` · `npm run dev` เปิดไฟล์จาก `web/` โดยตรง แก้แล้วรีเฟรชก็เห็นทันที ส่วนตัวแฟลชผ่าน USB และไฟล์สำหรับ Arduino IDE มาจาก `npm run build`

### Build firmware ใหม่

ติดตั้ง Arduino CLI 1.5.1 พร้อม core และไลบรารีตามรายการด้านล่าง หรือใช้ Arduino IDE ซึ่งมี CLI อยู่ข้างใน (script หา path มาตรฐานบน Windows ให้เอง)

```sh
arduino-cli config init
arduino-cli config add board_manager.additional_urls https://espressif.github.io/arduino-esp32/package_esp32_index.json
arduino-cli core update-index
arduino-cli core install esp32:esp32@3.3.11
arduino-cli lib install "Adafruit GFX Library@1.12.6" "Adafruit BusIO@1.17.4" "Adafruit ST7735 and ST7789 Library@1.11.0" "Adafruit GC9A01A@1.1.1" "Adafruit SSD1306@2.5.17" "Adafruit Unified Sensor@1.1.15"
npm run firmware
npm test
npm run build
```

`npm run firmware` build ครบ 15 ชุด เลือกบอร์ดหรือจอเฉพาะได้ เช่น `npm run firmware -- esp32-c3-supermini` (5 แบบจอ), `npm run firmware -- tft-240x240-gc9a01` (3 บอร์ด) หรือ `npm run firmware -- esp32-30pin oled-128x64` (1 ชุด เร็วที่สุดเมื่อจะลองบนบอร์ด) บอร์ดต่าง ๆ build พร้อมกันได้สูงสุด 3 บอร์ดเมื่อเครื่องมี CPU 12 thread ขึ้นไป ปรับได้ด้วย `FIRMWARE_BOARD_CONCURRENCY` และ `FIRMWARE_JOBS` (จำนวน compiler ต่อบอร์ด) บน Windows ถ้ายกเว้นโฟลเดอร์ `work\` และ `%LOCALAPPDATA%\Arduino15` จากการสแกนแบบ real-time ของ Microsoft Defender จะ build เร็วขึ้นมาก ถ้า toolchain อยู่ที่อื่น ให้ตั้ง environment `ARDUINO_CLI`, `ARDUINO_DATA_DIR` หรือ `ESPTOOL`

script จะทำตามลำดับนี้

1. stage ไฟล์ `tilt_toy.ino`, `config.h`, `flip_fluid.h`, `motion_sensor.h`, `motion_state.h`, `pixel_flow.h` และ `toy_modes.h`
2. compile ด้วย FQBN `esp32:esp32:esp32`, `esp32c3` หรือ `esp32c6` ตามบอร์ด ตั้ง DIO, Flash 4M, partition `huge_app` คือ app 3MB ไม่มี OTA และเปิด USB CDC สำหรับ C3/C6
3. merge bootloader@0x1000 สำหรับ ESP32 หรือ @0 สำหรับ C3/C6, partitions@0x8000, boot_app0@0xe000 และ app@0x10000 เป็นไฟล์เดียวที่แฟลช @0 (ESP32 มี padding ด้านหน้า)
4. สร้าง manifest ใหม่ ซึ่งเก็บ SHA-256 ของ binary และ `sourceSha256` ของ source ทั้งเจ็ดไฟล์

ผล compile อยู่ใน `work/firmware/run-<pid>/<board-id>/` แต่ละรอบและแต่ละบอร์ดแยก staging และ cache เพื่อไม่ให้ build ที่รันพร้อมกันสลับโปรไฟล์กัน ส่วน artifacts ของ C6 อยู่ใน `web/firmware/` เพื่อรักษา URL เดิม; ESP32 และ C3 อยู่ในโฟลเดอร์ย่อย `esp32-30pin/` และ `esp32-c3-supermini/` ตามลำดับ `npm test` จะ fail ถ้าแก้ source แล้วไม่ได้ build firmware ใหม่ ตั้ง `FIRMWARE_WORK_DIR` เพื่อใช้ cache เดิมได้เมื่อไม่มี build อื่นใช้โฟลเดอร์นั้น

ใน Arduino IDE เลือก ESP32 Dev Module, ESP32C3 Dev Module หรือ ESP32C6 Dev Module และตัวเลือก Flash/partition ตาม `web/boards.js` ส่วน `config.h` เลือก GPIO จาก target chip ให้อัตโนมัติ การตั้ง `BOARD_PROFILE` ให้ขัดกับ target จะคอมไพล์ไม่ผ่าน

ไดรเวอร์เซนเซอร์ใช้ `Wire` โดยตรง ไม่ต้องลงไลบรารีเซนเซอร์เพิ่ม `npm test` ทดสอบ C++ driver กับ I²C จำลองและตรวจ JS/C++ parity ด้วย `g++` หรือ compiler ในตัวแปร `CXX` (`clang++` / `cl` ใช้ได้) ถ้าไม่มี host compiler จะข้าม test ที่ต้องคอมไพล์ C++ สำหรับ MSVC ให้รันใน Developer Command Prompt โดยตั้ง `CXX=cl`

## โครงสร้าง

- `firmware/tilt_toy/`: sketch, IMU, 5 โหมด, ตาหุ่นยนต์, FLIP และ Pixel Flow solver, Wi-Fi UI, NVS
- `web/`: installer, preview, คำแปลอังกฤษ/ไทยใน `i18n.js`, profile contract, firmware artifacts และ licenses
- `scripts/`: build เว็บ, build/merge firmware และ local server
- `tests/`: ตรวจ profile, การต่อสาย, binary header/chip, partition, checksum และ source hash
- `docs/`: [แผนพัฒนา](docs/PLAN.md), [ฮาร์ดแวร์](docs/HARDWARE.md), [ผลตรวจ](docs/VALIDATION.md) และ [GitHub Pages](docs/GITHUB-PAGES.md)
- `.github/workflows/`: `ci.yml` ตรวจเว็บและ build firmware ครบทุกโปรไฟล์ ส่วน `pages.yml` deploy เว็บเมื่อ push ขึ้น `main`

เว็บ build ออกมาเป็น static files ใน `dist/` และ bundle ESP Web Tools ไว้ในตัว จึง host บน HTTPS host ไหนก็ได้
